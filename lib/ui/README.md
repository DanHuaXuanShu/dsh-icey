# lib/ui/ —— 通用界面层

这里放**跟具体游戏无关**的画面识别。换一个游戏时，这一层应该能整包复用。

## 该放什么

| 文件 | 管什么 |
|---|---|
| `scan.mjs` | 像素统计原语：区域亮度、帧差、全屏亮比。**不含任何坐标**，坐标由调用方传 |
| `execute-keycap.mjs` | 键帽图标识别（黑底 + 白色字母的方块，比如处决提示的 L） |
| `guide-arrow.mjs` + `arrow-template.mjs` | 方向箭头识别 |
| `chest-match.mjs` + `chest-template*.mjs` | 宝箱识别（暗底 + 青色边框 + 钱符号） |

## 硬规则（selfcheck 会检）

**这一层不许 import 任何 `games/` 下的东西。**

理由：界面层一旦依赖具体游戏，就复不了用，而且会形成环——
`games/icey/layout.mjs` 提供坐标给 `ui/` 用，`ui/` 再加个 import 回来，
改任何一个都得同时想两边。

正确的方向永远是单向的：

```
games/icey/  ──依赖──▶  ui/  ──依赖──▶  无（只依赖 Node 内置）
```

## 怎么加一个新游戏

1. 新建 `lib/games/<名字>/layout.mjs`，写这个游戏的区域和阈值
2. 调 `ui/scan.mjs` 的原语算指标
3. `ui/` 一个字都不用改

如果发现必须改 `ui/` 才能支持新游戏，说明它被写脏了——把它改成参数化的，
而不是在新游戏里复制一份。
